# ChainEye 심사 시연 가이드

## 한 문장 소개

ChainEye는 비트코인 거래 하나를 입력하면 미래 시점 검증을 거친 모델이 위험을 판정하고, 자금흐름과 판단 근거, 조사 보고서 초안을 한 화면에서 제공하는 분석 도구다.

## 3분 시연 순서

### 0:00~0:30 문제와 검증 근거

첫 화면에서 데이터셋 규모와 미래 시점 테스트 지표를 짚는다.

- Elliptic 거래 203,769건, 엣지 234,355건
- 미래 구간 테스트 16,670건
- 불법 클래스 F1 0.805, Precision 0.894, PR-AUC 0.799
- 라이브 LightGBM 입력 165개: 거래 자체 로컬 피처 93개 + 그래프 이웃 집계 피처 72개
- 그래프 이웃 집계 특성 포함 시 미래 테스트 F1 0.744 → 0.805, 절대값 +0.061
- 테스트 구간을 모델 선택에 쓰지 않은 rolling temporal validation

핵심 멘트: "무작위 분할 점수가 아니라 과거로 학습해 미래 거래를 맞히는 조건으로 검증했습니다."

### 0:30~1:30 고위험 거래 분석

`고위험 거래` 버튼을 누른다. 예상 결과는 다음과 같다.

- 거래 ID: `232629023`
- 위험 점수: 100점, 모델 판정 `illicit`
- 추적 결과: 노드 9건, 자금 이동 8건, 고위험 노드 2건
- 판단 근거: 사람이 읽을 수 있는 피처 그룹과 원본 `feat_*` ID를 함께 표시

위험 점수만 보여주는 것이 아니라 모델 근거, 방향성 자금흐름, 후속 조치가 같은 사건 단위로 연결된다는 점을 강조한다.

### 1:30~2:20 정상 거래 비교

`정상 거래` 버튼을 누르고 고위험 사례와 결과가 달라지는 모습을 보여준다. 임의로 만든 데모 값이 아니라 배포된 LightGBM이 실제 Elliptic 특성을 읽어 판정한다는 점은 상단 `MODEL API` 배지로 확인한다.

### 2:20~3:00 실무 적용과 안전장치

- 자동 보고서는 초안이며 최종 판단은 담당 분석관이 검토한다.
- Claude Opus 5 호출이 실패하거나 키가 없어도 결정론적 템플릿으로 보고서가 생성된다.
- 미등록 거래는 404, 추론 장애는 503으로 반환해 가짜 점수로 정상처럼 보이지 않게 한다.
- `/health`는 모델 적재 상태를, `/model-info`는 배포 모델의 성능 근거를 공개한다.

## 예상 질문과 답변

### 왜 Accuracy 대신 F1과 PR-AUC를 썼나?

불법 거래가 적은 불균형 데이터에서는 정상 거래만 잘 맞혀도 Accuracy가 높게 보일 수 있다. 그래서 불법 클래스 Precision과 Recall의 균형인 F1, 양성 희소성을 반영하는 PR-AUC를 대표 지표로 사용했다.

### 데이터 누수는 어떻게 막았나?

시간 순서를 유지했다. 세 개의 과거→미래 rolling validation 구간으로 트리 수와 임계값을 정한 뒤, 가장 뒤의 time step 35~49는 최종 평가에만 한 번 사용했다.

### GCN도 실제 판정에 쓰나?

아니다. standalone end-to-end GCN은 별도 평가에서 라이브 LightGBM보다 낮아 제외했다. 현재 라이브 모델은 거래 자체 로컬 피처 93개와 그래프 이웃 집계 피처 72개를 함께 받는 LightGBM이며, GCN은 추론 API에 연결되어 있지 않다.

### 그래프 정보를 쓰는데 왜 GCN이 아닌가?

그래프 정보는 이미 이웃 집계 피처 72개로 라이브 LightGBM에 반영된다. 동일한 rolling validation과 미래 테스트 조건의 ablation에서 거래 자체 특성만 쓴 모델은 F1 0.744, 그래프 집계 특성을 포함한 모델은 0.805로 +0.061 상승했다. end-to-end GCN은 그래프를 직접 전파하는 별도 접근으로 검토했지만 더 낮은 성능을 보여 배포하지 않았다.

### 생성형 AI가 잘못된 내용을 쓰면 어떻게 하나?

LLM에는 점수, 모델 라벨, 상위 기여 특성, 그래프 통계만 전달하고 새로운 사실을 만들지 않도록 제한한다. 외부 API가 실패하면 같은 입력으로 결정론적 템플릿을 만들며, 모든 보고서에 담당자 검토 문구를 표시한다.

## 제출 직전 체크리스트

- 공개 URL 첫 화면이 30초 안에 열리는가
- `/health`가 HTTP 200, `modelLoaded=true`, `mode=model`인가
- `/model-info` 지표가 `app/ml/metrics.json`과 일치하는가
- 고위험, 정상, 미라벨 거래 버튼이 각각 한 번에 실행되는가
- 그래프 확대·축소, 보고서 복사, 모바일 폭에서 레이아웃이 정상인가
- 브라우저 콘솔에 오류나 경고가 없는가
- 심사 기간 동안 무료 인스턴스 슬립이 비활성화되어 있는가
