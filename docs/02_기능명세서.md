## 1. 문서 개요

### 1.1 서비스명 및 목적
체인아이(ChainEye)는 비트코인 트랜잭션 그래프에서 자금세탁 의심 거래를 탐지하고, 대상 거래의 상·하류 자금흐름을 시각적으로 추적하며, 판정 근거(XAI)와 함께 수사·컴플라이언스 담당자용 한국어 리포트를 자동 생성하는 웹서비스이다. 이 문서는 이미 구현되어 동작 중인 서비스의 기능을 명세한다.

### 1.2 문서 범위
본 명세서는 체인아이의 실제 구현물(프론트엔드, 백엔드 API, ML 추론 모듈, 학습 모델·데이터 산출물)을 대상으로 다음을 기술한다.
- 시스템 구성 및 계층 구조
- 제공 기능 목록과 기능별 상세 명세
- REST API 엔드포인트별 요청/응답 규격
- 학습 데이터 및 AI 모델 구성·성능
- 화면 구성 및 비기능 요구사항, 제약사항·향후계획

본 문서에 기술된 성능지표·API 규격·데이터 수치는 실제 소스코드 및 산출물(`app/ml/metrics.json`, `app/backend/main.py`, `app/ml/inference.py`)과 교차 검증된 값이다.

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| txId | 비트코인 트랜잭션 식별자. Elliptic 데이터셋에서는 익명화된 정수 ID이다. |
| illicit / licit | 불법(자금세탁 의심) / 합법(정상) 거래 라벨 |
| 리스크 스코어(riskScore) | 모델이 산출한 불법 확률을 0~100 정수로 환산한 위험 점수 |
| SHAP | 모델 판정에 대한 각 피처의 기여도를 산출하는 설명가능성(XAI) 기법 |
| topFactors | 특정 판정에서 기여도 상위 피처 목록(부호 있는 SHAP 값 포함) |
| hop | 그래프 추적 시 대상 노드로부터의 이웃 확장 단계 수 |
| 템포럴 분할(temporal split) | 시간축(타임스텝) 기준 학습/검증 분할. 무작위 분할과 달리 미래 시점 데이터 누수를 방지 |
| MODEL / MOCK 모드 | 실제 학습 모델로 응답하는 모드 / 모델 미로딩 시 동일 스키마의 샘플 데이터로 응답하는 폴백 모드 |
| STR | 의심거래보고(Suspicious Transaction Report) |

## 2. 시스템 구성도

체인아이는 프론트엔드 → 백엔드 API → 모델·데이터 계층의 3계층 구조이다.

```
┌──────────────────────────────────────────────────────────────┐
│  [프레젠테이션 계층]  React + Vite SPA  (http://localhost:5173) │
│   InputBar · RiskPanel · GraphPanel(Cytoscape.js) · ReportPanel│
│   config.js(API_BASE / USE_MOCK) · api.js(fetch 래퍼)          │
└───────────────────────────┬──────────────────────────────────┘
                            │  HTTP / JSON (CORS 허용)
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  [애플리케이션 계층]  FastAPI 백엔드  (http://localhost:8000)   │
│   GET  /health   상태 · 모델 로드 여부                          │
│   POST /score    위험 점수 + 라벨 + topFactors(SHAP)           │
│   POST /trace    자금흐름 서브그래프(nodes/edges)              │
│   POST /explain  판정 근거(topFactors) 조회                    │
│   POST /report   템플릿 기반 한국어 분석 보고서                │
│   · 기동 시 ML 모듈 import 시도 → 성공: MODEL / 실패: MOCK 폴백 │
└───────────────────────────┬──────────────────────────────────┘
                            │  in-process 함수 호출 (loose coupling)
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  [모델·데이터 계층]  app/ml/inference.py                       │
│   chaineye_model.pkl (LightGBM)  ·  shap.TreeExplainer         │
│   feature_table.parquet (203,769 노드 × 165 피처: 거래 자체 93 + 이웃 집계 72) │
│   edges.parquet (방향 엣지) → 무방향 인접리스트(그래프 추적)   │
└──────────────────────────────────────────────────────────────┘
```

**연동 특성(loose coupling):** 백엔드는 기동 시 `app/ml/inference.py` 를 import·load 시도한다. 성공하면 `/score`·`/trace` 는 실제 모델로 위임(MODEL 모드)되고, 실패하면 동일 스키마의 샘플 데이터를 반환하는 내장 mock provider로 폴백(MOCK 모드)하여 ML 준비 여부와 무관하게 API가 항상 응답한다.

## 4. 기능별 상세 명세

### F-01 리스크 스코어링
- **입력:** 트랜잭션 ID(txId, 문자열)
- **처리:**
  1. txId를 정수로 변환 후 피처 테이블(`feature_table.parquet`)에서 165차원 피처 벡터를 조회한다. 벡터는 거래 자체의 로컬 피처 93개와 거래 그래프 이웃을 집계한 피처 72개로 구성된다.
  2. LightGBM `predict_proba` 로 불법 확률 산출, `round(proba × 100)` 로 0~100 위험 점수 환산
  3. rolling validation에서 선택한 임계값(현재 0.5238)으로 라벨 결정(`illicit` / `licit`)
  4. `shap.TreeExplainer` 로 해당 예측의 피처 기여도 산출, 절댓값 상위 6개를 topFactors로 반환
  - ML 모듈 직접 호출은 미등록 txId에 안전 기본값을 반환한다. 공개 API는 오판 방지를 위해 미등록 txId에 HTTP 404를 반환한다.
- **출력:** riskScore(0~100), label, topFactors(최대 6개, 부호 있는 SHAP impact)
- **화면:** 위험도 패널(좌): SVG 게이지 + 등급 배지 + 핵심 위험 근거 목록
- **관련 API:** `POST /score`

### F-02 자금흐름 추적
- **입력:** txId, hops(1~4, 기본 2)
- **처리:**
  1. 방향 엣지리스트로부터 구성한 무방향 인접리스트에서 대상 노드 기준 BFS로 hop 단계까지 이웃 확장
  2. 노드 수가 상한(약 60개)을 초과하면 위험 점수 높은 이웃 우선으로 절단(대상 노드는 항상 포함)
  3. 각 노드에 위험 점수 부여, `focus` 플래그로 대상 노드 표시
  4. 유지된 노드 집합 내부의 엣지만(원본 방향 유지) 반환
  - 그래프에 없는 노드는 대상 노드 단독(엣지 없음)으로 반환
- **출력:** nodes(id, risk 0~100, focus, illicit), edges(source, target), paths(List[List[str]])
- **화면:** 자금 흐름 그래프 패널(중앙): Cytoscape.js 방향 그래프
- **관련 API:** `POST /trace`

### F-03 설명가능성(XAI)
- **입력:** txId
- **처리:** 스코어링 provider의 SHAP 기여도(topFactors)를 재사용하여 판정 근거만 반환. 각 항목은 피처명과 부호 있는 기여도(impact)로 구성되며, 양수는 위험도 상승, 음수는 하락 방향을 의미
- **출력:** txId, topFactors
- **화면:** 위험도 패널의 "핵심 위험 근거" 영역 및 리포트의 【핵심 판단 근거】 절
- **관련 API:** `POST /explain` (내부적으로 `/score` provider 재사용)

### F-04 자동 보고서
- **입력:** txId, score(0~100), label, topFactors, graphStats(nodeCount, edgeCount, highRiskCount, hops; 구 스키마 illicitNeighbors 폴백 호환)
- **처리:** `CHAINEYE_REPORT_PROVIDER`에 따라 Claude Opus 5, OpenAI Responses API, 자동 순차 시도, 템플릿 전용 경로를 선택한다. SDK·키·네트워크·API 오류 시 `report_builder.build_report`의 결정론적 템플릿으로 폴백한다.
- **출력:** report(문자열, 구획선 포함 서식 텍스트)
- **화면:** AI 조사 리포트 패널(우): 경량 마크다운 렌더링
- **관련 API:** `POST /report`

### F-05 그래프 시각화
- **입력:** `/trace` 응답(nodes/edges)
- **처리:** Cytoscape.js로 방향 그래프 렌더링. 대상/고위험 노드는 빨강, 일반 노드는 회색으로 표시하여 위험 경로를 시각적으로 강조
- **출력:** 인터랙티브 그래프 뷰
- **화면:** 자금 흐름 그래프 패널(중앙, `GraphPanel.jsx`)

### F-06 상태 점검(헬스체크)
- **입력:** 없음
- **처리:** 서비스 상태와 실제 모델 로드 여부(`modelLoaded`) 반환. MODEL/MOCK 모드 판별에 사용
- **출력:** status, modelLoaded, mode(`model` 또는 `mock`)
- **관련 API:** `GET /health`

### F-06A 모델 근거 공개
- **입력:** 없음
- **처리:** 버전 관리되는 `app/ml/metrics.json`에서 실제 배포 모델의 평가 근거를 읽어 반환
- **출력:** 데이터셋 규모, 학습·테스트 표본 수, 불법 클래스 Precision·Recall·F1, PR-AUC, ROC-AUC, 판정 임계값, 시간 순서 검증 방식
- **관련 API:** `GET /model-info`

### F-07 데모/실서비스 전환
- **처리:** 프론트엔드 `src/config.js` 의 `USE_MOCK` 플래그로 샘플 데이터(백엔드 불필요)와 실제 API 호출을 전환. 백엔드도 모델 미로딩 시 MOCK 모드로 자동 폴백하여 이중 안전장치 제공
- **관련 설정:** `config.js`(프론트), `STATE.mode`(백엔드)

### F-08 의심 자금세탁 경로 탐지·시각화
- **입력:** 대상 txId, hops(1~4)
- **처리:**
  1. `/trace` 로 구성된 추적 이웃(노드 상한 60개) 위에서, 유지된 노드 간 원본 방향(directed) 엣지로 방향성 인접리스트를 구성
  2. 대상(focus) 노드에서 출발하는 방향성 워크(directed walk) 탐색으로, 고위험 노드(위험도 70 이상)에서 끝나는 경로를 수집. 경로 길이는 노드 기준 2 ~ hops+1(엣지 1 ~ hops)이며, 단일 경로 내 사이클은 배제
  3. 중복 경로를 제거하고 최대 8개까지 반환
  4. 각 노드에는 위험도 70 이상 여부를 나타내는 `illicit`(bool) 플래그를 함께 부여
- **출력:** 응답 최상위 `paths`(List[List[str]]), txId 문자열의 순서 있는 목록. 대상 노드에서 시작해 고위험 노드에서 종료. 각 노드의 `illicit` 플래그 포함
- **화면:** 자금 흐름 그래프 패널(중앙, `GraphPanel.jsx`): 경로 엣지를 주황색 marching-ants(행진 개미) 애니메이션으로 강조하고 범례에 "의심 자금세탁 경로" 항목 표시
- **관련 API:** `POST /trace`

## 5. API 명세

- **Base URL:** `http://localhost:8000`
- **인코딩:** 요청·응답 모두 `application/json`
- **CORS 허용 오리진:** `http://localhost:5173`, `http://localhost:3000`
- **API 버전:** 0.1.0 · **문서(Swagger):** `/docs`

### 5.1 GET /health: 상태 점검
- **목적:** 서비스 및 모델 로드 여부 확인

**응답 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| status | string | 서비스 상태(기본 "ok") |
| modelLoaded | boolean | 실제 ML 모델 로드 여부(true=MODEL, false=MOCK) |
| mode | "model" \| "mock" | 현재 요청을 처리하는 데이터 공급자 모드 |

**예시**
```
GET /health
→ {"status": "ok", "modelLoaded": true, "mode": "model"}
```

### 5.2 GET /model-info: 모델 근거 조회

- **목적:** 화면에 표시하는 성능 수치와 배포 모델 산출물의 단일 출처를 제공
- **오류:** 지표 파일이 없거나 필드가 손상되면 HTTP 503을 반환하며 임의 수치로 대체하지 않음

**주요 응답 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| active | boolean | 실제 모델 적재 여부 |
| activeModel | string | 라이브 판정 모델과 그래프 특성 사용 방식 |
| dataset | string | 평가 데이터셋 |
| trainSamples / testSamples | int | 최종 학습·미래 테스트 표본 수 |
| illicitF1 / illicitPrecision / illicitRecall | float | 불법 클래스 성능 |
| prAuc / rocAuc | float | 불균형 분류 및 순위 성능 |
| decisionThreshold | float | 라이브 라벨 판정 임계값 |
| validationProtocol | string | 모델 선택과 최종 평가 분리 방식 |
| featureCount / localFeatureCount / neighborAggregateFeatureCount | int | 전체·거래 자체·그래프 이웃 집계 특성 수 |
| localOnlyF1 / graphEnhancedF1 / graphF1Lift | float | 동일 프로토콜의 그래프 특성 ablation 결과 |

### 5.3 POST /score: 리스크 스코어링
- **목적:** 단일 거래의 위험 점수·라벨·판정 근거 산출

**요청 필드**

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|

**응답 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| txId | string | 대상 트랜잭션 ID |
| riskScore | int(0~100) | 위험 점수 |
| label | "illicit" \| "licit" | 판정 라벨(`metrics.json`의 검증 임계값 적용) |

### 5.4 POST /trace: 자금흐름 추적
- **목적:** 대상 노드 기준 이웃 서브그래프 생성

**요청 필드**

| 필드 | 타입 | 필수 | 기본 | 설명 |
|---|---|---|---|---|
| txId | string | Y | — | 추적 시작 트랜잭션 ID |
| hops | int(1~4) | N | 2 | 이웃 확장 단계 수 |

**응답 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| nodes | array | 노드 목록(최대 약 60개) |

| nodes[].illicit | boolean | 고위험 여부(위험도 70 이상) |
| edges | array | 유지된 노드 간 방향 엣지 |
| edges[].source | string | 출발 노드 ID |
| edges[].target | string | 도착 노드 ID |
| paths | array(List[List[str]]) | 의심 자금세탁 경로. 대상 노드에서 출발해 고위험 노드에서 끝나는 방향성 워크(길이 2~hops+1 노드), 중복 제거 후 최대 8개 |

**예시**
```
POST /trace  {"txId": "232629023", "hops": 2}
→ {
    "nodes": [
      {"id": "232629023", "risk": 100, "focus": true, "illicit": true},

      {"id": "231044559", "risk": 84, "focus": false, "illicit": true}
    ],
    "edges": [
      {"source": "232629023", "target": "231981037"},
      {"source": "231981037", "target": "231044559"}
    ],
    "paths": [
      ["232629023", "231981037", "231044559"]
    ]
  }
```

### 5.6 POST /report: 자동 보고서 생성
- **목적:** 점수·근거·그래프 통계를 종합한 한국어 분석 보고서 생성

**요청 필드**

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| txId | string | Y | 대상 트랜잭션 ID |
| score | int(0~100) | Y | 위험 점수 |
| label | string | Y | 라벨(illicit/licit) |
| topFactors | array | N | 판정 근거(feature, impact), 기본 [] |
| graphStats | object | N | 그래프 통계 |
| graphStats.nodeCount | int | N | 추적 노드 수(기본 0) |
| graphStats.edgeCount | int | N | 자금 이동(엣지) 건수(기본 0). 보고서의 "자금 이동 N건" 표기에 사용 |
| graphStats.highRiskCount | int | N | 고위험(위험도 70+) 노드 수(기본 0). 프론트엔드가 전송하는 위험 이웃 지표 |
| graphStats.illicitNeighbors | int | N | (구 스키마) 위험 이웃 노드 수. 전달되면 우선 사용, 없으면 highRiskCount 로 폴백 |
| graphStats.hops | int | N | 추적 hop 수(기본 0) |

> **graphStats 처리(정합화됨):** `highRiskCount`는 추적 그래프 전체의 고위험 노드 수다. 대상(focus) 노드 자신이 고위험이면 연결 노드 통계에서 1을 차감한다. 구 스키마 `illicitNeighbors`는 이미 대상을 제외한 값으로 간주한다. 직접 연결 여부는 그래프 통계만으로 단정하지 않으며, `edgeCount`는 "자금 이동 N건"으로 표기한다.

**응답 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| report | string | 서식화된 한국어 보고서 텍스트 |

**예시**
```
POST /report  {
  "txId": "232629023", "score": 100, "label": "illicit",
  "topFactors": [{"feature": "feat_58", "impact": 0.62}],
  "graphStats": {"nodeCount": 41, "edgeCount": 58, "highRiskCount": 8, "hops": 2}
}
→ {"report": "━━━ 체인아이(ChainEye) 자금세탁 위험 분석 보고서 ━━━ ..."}
```

## 6. 데이터 명세

### 6.1 Elliptic 데이터셋 개요
Elliptic사가 공개한 익명화된 실제 비트코인 트랜잭션 그래프를 학습·검증에 사용한다.

| 항목 | 값 |
|---|---|
| 노드(트랜잭션) 수 | 203,769 |
| 엣지(비트코인 흐름) 수 | 234,355 |
| 타임스텝 수 | 49 |
| 원본 피처 수 | 166 (시간축 1 + 거래 자체 로컬 93 + 이웃 집계 72) |
| 라벨 분포 | 불법 2%(4,545) / 합법 21%(42,019) / 미분류 77% |

### 6.2 전처리 및 산출물
학습 파이프라인(`app/ml/train.py`)은 원본 Elliptic CSV(features.csv 약 665MB)를 float32 다운캐스팅으로 1회 읽어 다음 산출물을 생성한다(전체 약 30초).

| 산출물 | 용도 |
|---|---|
| `chaineye_model.pkl` | 학습된 LightGBM 분류기(joblib) |
| `feature_table.parquet` | 전체 203,769 노드의 165 피처(txId 인덱스, 추론용) |
| `edges.parquet` | 방향 엣지리스트(txId1 → txId2) |
| `shap_background.parquet` | SHAP 배경 표본 |
| `feature_importance.csv` | 전역 SHAP 평균 절댓값 중요도 |
| `metrics.json` | 평가 지표 |

> **피처 수 주석:** 원본의 166개 피처는 시간축 컬럼 1개, 거래 자체 로컬 피처 93개, 그래프 이웃 집계 피처 72개로 구성된다. 추론 모듈(`inference.py`)은 시간축 컬럼(time_step)을 제외한 165개(93 + 72)를 모델 입력으로 사용한다. `feat_i`는 익명화된 입력 피처의 i번째 컬럼을 의미한다.

### 6.3 학습/테스트 분할 (템포럴 분할)
데이터 누수를 방지하기 위해 무작위 분할 대신 시간축 기준 분할을 적용한다.

| 구분 | 타임스텝 | 라벨 표본 수 | 불법 표본 수 |
|---|---|---|---|
| 학습(train) | 1 ~ 34 | 29,894 | 3,462 |
| 테스트(test) | 35 ~ 49 | 16,670 | 1,083 |

학습 구간 내부에서 `(1~19 → 20~24)`, `(1~24 → 25~29)`, `(1~29 → 30~34)`의 세 개 rolling validation fold를 사용한다. 평균 PR-AUC로 트리 수를 고르고, fold별 불법 F1 최적 임계값의 중앙값을 서비스 임계값으로 고정한 뒤 1~34 전체를 재학습한다. 테스트 35~49는 최종 성능 산출 전까지 모델·임계값 선택에 사용하지 않는다.

미분류(unknown) 라벨은 학습·평가에서 제외하되, 피처가 있는 미분류 거래도 추론 시점에는 정상적으로 점수화된다.

## 7. AI 모델 명세

### 7.1 모델 구성
- **알고리즘:** LightGBM 이진 분류기(불법=양성 클래스)
- **입력:** 165차원 피처 벡터(거래 자체 로컬 피처 93개 + 그래프 이웃 집계 피처 72개)
- **출력:** 불법 확률(0~1) → 0~100 위험 점수 및 검증 기반 임계값(현재 0.5238) 기준 라벨
- **클래스 불균형 대응:** `scale_pos_weight = 7.63`
- **모델 선택:** 과거 구간 세 개를 굴리는 rolling temporal validation의 평균 PR-AUC로 트리 수 선택
- **선택 반복(best_iteration):** 600
- **설명가능성:** `shap.TreeExplainer`. 예측별 피처 기여도(부호 포함) 및 전역 중요도 산출

### 7.2 성능 지표 (테스트셋, 템포럴 분할, 불법=양성)

| 지표 | 값 |
|---|---|
| Illicit Precision | 0.8940 |
| Illicit Recall | 0.7322 |
| **Illicit F1 (대표 지표)** | **0.8051** |
| PR-AUC (Average Precision) | 0.7995 |
| ROC-AUC | 0.9317 |

불균형 데이터 특성상 Accuracy 대신 불법 클래스 기준 F1·PR-AUC를 대표 지표로 사용한다. 트리 수와 임계값은 테스트셋이 아닌 세 개의 rolling validation 구간에서 결정했으며, 35~49 미래 테스트 구간은 마지막 평가에만 사용했다.

**혼동 행렬 (검증 임계값 0.5238, 행=실제 / 열=예측)**

|  | 예측 licit | 예측 illicit |
|---|---:|---:|
| 실제 licit | 15,493 (TN) | 94 (FP) |
| 실제 illicit | 290 (FN) | 793 (TP) |

### 7.3 SHAP 기반 설명
- **전역 중요도 상위 피처:** feat_58, feat_52, feat_75, feat_57, feat_4, feat_124
- **예측별 설명:** `/score`·`/explain` 응답의 topFactors로 절댓값 상위 6개 피처를 부호 있는 기여도와 함께 제공. 양수는 위험도 상승, 음수는 하락 방향으로 해석된다.

### 7.4 그래프 이웃 집계 특성 ablation

거래 자체 로컬 피처 93개만 사용한 LightGBM과 그래프 이웃 집계 피처 72개를 더한 라이브 LightGBM을 동일한 rolling validation 및 미래 테스트 조건으로 비교했다.

| 피처 구성 | Illicit F1 | PR-AUC |
|---|---:|---:|
| 거래 자체 93개 | 0.7440 | 0.7858 |
| 거래 자체 93개 + 그래프 이웃 집계 72개 | **0.8051** | **0.7995** |
| 그래프 특성의 절대 향상 | **+0.0611** | **+0.0137** |

트리 수와 임계값은 각 피처 구성의 rolling validation에서 독립적으로 선택했고, time step 35~49는 최종 평가에만 사용했다. 전체 산출물과 재현 코드는 `app/ml/ablation_metrics.json`, `app/ml/evaluate_feature_ablation.py`에 있다.

### 7.5 그래프 신경망(GCN) 평가와 배제 결정

그래프 구조를 직접 전파하는 standalone end-to-end GCN도 별도로 학습·평가했다. 그러나 동일한 미래 시점 평가 조건에서 라이브 LightGBM보다 성능이 낮았으므로, 현재 판정 경로에서는 제외했다. 이는 LightGBM이 그래프 정보를 쓰지 않는다는 뜻이 아니다. 라이브 LightGBM은 거래 자체 로컬 피처 93개에 그래프 이웃 집계 피처 72개를 결합해 사용한다.

- **위치:** `app/ml/gcn/`(`gcn_train.py`, `gcn_model.pt`, `gcn_metrics.json`, `README.md`)
- **상태:** 독립 연구 산출물. `inference.py` 및 백엔드에 연결되어 있지 않으며 `/score`·`/trace`의 라이브 판정에 사용되지 않는다.
- **심사 설명 원칙:** 7.4의 피처 ablation과 standalone GCN 비교는 서로 다른 실험이다. GCN 결과를 피처 제거·추가 효과로 해석하지 않는다.

> **주석:** 입력바를 포함하면 화면은 4개 영역으로 구성되나, 결과 표시 패널은 위험도·그래프·리포트의 3패널이다.

## 10. 제약사항 및 향후계획

### 10.1 현재 제약사항 (구현 범위 명시)
- **그래프 신경망(GCN)은 평가 후 라이브에서 제외:** standalone end-to-end GCN은 `app/ml/gcn/`에 독립 산출물로 남아 있으나, 미래 시점 평가에서 라이브 LightGBM보다 낮아 `inference.py`·백엔드에 연결하지 않았다. 현재 라이브 판정은 거래 로컬 93개와 그래프 이웃 집계 72개를 함께 사용하는 LightGBM 단일 경로다.
- **자동 보고서(LLM):** Claude Opus 5(`claude-opus-5`)와 OpenAI Responses API가 구현되어 있다. 외부 호출은 선택 사항이며 템플릿 폴백은 항상 유지한다.
- **피처 한글 매핑:** 보고서 생성기는 일부 의미형 피처명(예: mixer_exposure_ratio)에 대한 한글 라벨 사전을 갖고 있으나, 실제 모델의 익명화 피처명(feat_i)은 사전에 없어 원문(feat_i)으로 표기된다.
- **`/report` 그래프 통계 필드 정합화(해결됨):** 백엔드 `GraphStats`는 `{nodeCount, edgeCount, highRiskCount, hops}`를 수용한다. `highRiskCount`는 추적 범위 전체의 고위험 노드 수로 해석하고 대상 노드 자신이 고위험이면 연결 노드 통계에서 1을 차감한다. 구 스키마 `illicitNeighbors`는 이미 대상을 제외한 값으로 호환한다. 직접 연결을 단정하지 않고 추적 범위 내 연결 노드라고 표현한다.
- **배포:** 프론트엔드와 백엔드를 단일 Docker 이미지로 패키징해 Render 공개 URL에서 서비스한다. 로컬 개발 환경은 프론트 :5173, 백엔드 :8000으로 분리한다.

### 10.2 향후계획
- 재현 가능한 비교·ablation 산출물을 갖춘 뒤 GCN/GraphSAGE/GAT 또는 앙상블의 재도입 여부를 재평가
- 기관별 프롬프트·감사 로그·민감정보 비식별화 정책을 추가하고 LLM 결과 품질 평가셋을 구축
- Elliptic++ / Elliptic2 등 대규모·서브그래프 데이터로 확장하고 배포 이중화 및 가용성 모니터링을 추가
