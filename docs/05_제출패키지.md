## 제출 화면용 서비스 설명

ChainEye는 블록체인 거래 ID 하나로 자금세탁 위험 점수, 방향성 자금흐름, 모델 판단 근거와 조사 보고서 초안을 함께 제공한다. Elliptic 데이터셋의 거래 자체 특성 93개와 그래프 이웃 집계 특성 72개를 결합한 LightGBM을 사용한다. 모델 선택은 세 개의 과거→미래 rolling validation 구간에서 수행했고, 마지막 time step 35~49는 선택 과정에서 분리한 미래 테스트로 유지했다. 해당 테스트에서 불법 클래스 F1 0.805, Precision 0.894, PR-AUC 0.799를 기록했다. 동일 조건의 ablation에서는 그래프 특성 추가로 F1이 0.744에서 0.805로 0.061 상승했다. 결과 화면은 점수만 제시하지 않고 SHAP 근거, 연결 거래와 후속 조치를 사건 단위로 묶는다. 외부 LLM 키가 없거나 호출에 실패해도 결정론적 보고서 템플릿으로 핵심 기능이 유지되며, 보고서는 담당자 검토가 필요한 초안임을 명시한다.

## 심사에서 먼저 보여줄 차별점

1. 무작위 분할이 아니라 과거 거래로 학습해 미래 거래를 판정하는 시간 순서 평가를 적용했다.
2. 그래프를 화면 장식으로만 쓰지 않고 이웃 집계 특성 72개를 라이브 모델에 입력했으며, ablation으로 F1 +0.061 효과를 검증했다.
3. 위험 점수, SHAP 근거, 방향성 자금흐름, 조사 보고서를 한 번의 조회로 연결한다.
4. 성능이 낮았던 standalone GCN은 과장해 배포하지 않고 비교 실험으로 분리했다.
5. `/health`와 `/model-info`에서 실제 모델 적재 여부와 평가 근거를 심사자가 직접 확인할 수 있다.

## 공개 배포 점검

저장소 루트에서 다음 명령을 실행한다.

```bash
python deploy/docker_smoke_test.py --base-url https://chaineye.onrender.com
```

수동으로도 아래 항목을 확인한다.

- `/health`: HTTP 200, `modelLoaded=true`, `mode=model`
- `/model-info`: `active=true`, `featureCount=165`, `illicitF1≈0.805`
- 예시 거래 `232629023`, `232438397`, `230425980`이 각각 한 번에 조회됨
- 첫 화면과 결과 화면에 `MODEL API`가 표시되고 브라우저 콘솔 오류가 없음
- API 키가 없는 상태에서도 보고서 생성이 성공함

## PDF 제작 전 확인

- 기획서와 기능명세서는 반드시 대회 제공 양식에 내용을 옮긴 뒤 PDF로 저장한다.
- 표·이미지가 페이지 밖으로 잘리지 않는지, 링크가 클릭되는지, 글꼴이 포함됐는지 확인한다.
- 모델 수치는 `app/ml/metrics.json`과 `app/ml/ablation_metrics.json`을 단일 근거로 사용한다.
- `AI 탐지 우회`, 워터마크 제거, 숨은 유니코드 삽입 같은 표현이나 처리는 사용하지 않는다. 활용한 데이터·라이브러리·생성형 AI는 사실대로 밝힌다.
- 파일명 예시: `ChainEye_기획서.pdf`, `ChainEye_기능명세서.pdf`
